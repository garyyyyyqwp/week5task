OCR 与图片理解 — 工具选择对比小结

文档日期：2026-07-05  |  基于 Week 5 AI 学习助手项目架构分析

核心结论：不是所有"图里有字"都要调视觉大模型

三种典型场景对"看懂图片"的需求完全不同，下面从成本、准确率、延迟三个维度做对比， 帮你判断什么时候该用专门 OCR、什么时候该用视觉大模型。

场景 ① 纯文字提取（票据 / 文档扫描）

场景描述

拍一张发票、收据或打印文档，只需要提取上面的文字，不需要"理解"内容含义。

对比

方案推荐度成本准确率延迟说明
专用 OCR API（百度 OCR / Tesseract / PaddleOCR） 推荐 极低
百度 OCR 每天 500 次免费		 高
对印刷体 99%+		 快
200-500ms		 专为文字提取优化，支持版面分析、表格识别，成本几乎为零
视觉大模型（glm-4.6v / GPT-4V） 不推荐 高
每张图约 ¥0.01-0.05		 高
也很准确		 慢
1-3s		 能提取，但用大炮打蚊子——功能和成本都不匹配

本项目实际做法

本项目没有接入专门 OCR，因为目标场景是"学习辅导"（看懂题目并讲解），不是"发票录入"。 如果需要文档扫描功能，可以在 app/services/ 下新增 ocr.py 封装百度 OCR SDK 作为独立工具。

场景 ② 图表理解（看懂趋势 / 数据关系）

场景描述

一张折线图、柱状图或饼图，需要理解数据趋势、比较大小、解读变化原因。

对比

方案推荐度成本准确率延迟说明
视觉大模型（glm-4.6v / GPT-4V） 推荐 中
每张图约 ¥0.01-0.03		 高
理解趋势和语义		 中
1-3s		 OCR 只能读出坐标轴数字，视觉模型能理解"增长趋势""拐点""异常值"
专用 OCR + 人工解读 不推荐 低 低
只能出数字，不解释含义		 快 OCR 出的是原始数字，无法回答"为什么 Q3 下降了"这类问题

本项目实际做法

这正是本项目的核心场景 — 学生拍一张带图表的数学题，模型要同时看懂文字和图表才能给出正确讲解。 多模态模型（glm-4.6v）是唯一正确的选择。

场景 ③ 手写题目识别（学生手写题拍照提问）

场景描述

学生手写了一道数学题或物理题，拍照让 AI 识别题目并讲解。

对比

方案推荐度成本准确率延迟说明
视觉大模型（glm-4.6v / GPT-4V） 推荐 中
每张图约 ¥0.01-0.03		 高
手写识别 + 语义理解一体化		 中
1-3s		 一步完成"识别手写字 → 理解题意 → 生成讲解"，无需拆分步骤
专用 OCR → 文本模型 视情况 低 中
手写 OCR 准确率约 85-95%		 中
OCR 500ms + LLM 1s		 如果题目没有图表/公式，纯文字 OCR 也可行，但手写识别错误率是瓶颈

本项目实际做法

本项目选择视觉大模型一步到位，因为题目往往包含手写公式、几何图形、坐标系等 OCR 无法正确处理的内容。 而且"识别 → 理解 → 讲解"在同一步完成，减少了中间环节出错的可能。

决策速查表

你的需求是...推荐工具理由
提取发票 / 收据上的文字 专用 OCR 成本极低、速度极快、准确率极高，不需要语义理解
看懂图表走势并解释原因 视觉大模型 OCR 只能读数字，无法理解趋势、拐点、异常值
识别手写题目并讲解 视觉大模型 手写+公式+图形需要综合理解，一步到位比 OCR→LLM 两步更可靠
批量处理 1 万张标准表单 专用 OCR 规模 × 视觉模型成本不可接受，OCR 批处理是最优解
识别图中有哪些物体并描述 视觉大模型 OCR 根本做不了，视觉模型是唯一选择

本项目立场

本项目的核心场景是学习辅导：学生拍照提问，AI 看图讲解。这个场景天然需要视觉理解而非纯文字提取。 因此选择 glm-4.6v 作为唯一推理模型，图片直入、一步到位。

如果未来需要处理大批量文档扫描（如学校试卷批量录入），可以在 app/services/tools.py 中新增一个 ocr_extract 工具， 对有明确"纯文字提取"需求的请求做路由分流。
