多模态对比实验记录

实验日期：2026-07-05  |  测试模型：智谱 GLM-4.6V (106B)  |  实验者：Week 5 AI 学习助手项目

1. 实验目的

验证"图片直入多模态模型"（一步直达）相比"图片先转文字摘要再进文本模型"（有损做法）的信息保真优势。 用同一张信息密集的图片，设计 3 个对视觉细节敏感的问题，对比两条链路的答案准确率。

2. 测试材料

测试图片

一张 含多个模块的系统架构图，包含：

  • 6 个功能模块（用户端、API 网关、消息队列、微服务集群、数据库集群、监控面板）
  • 模块之间的连接箭头和标注（如 gRPC、REST、WebSocket）
  • 每个模块右下角的吞吐量数值（如 2.4K req/s、850 req/s）
  • 右下角的配色图例（绿色=正常、黄色=告警、红色=故障）
[架构示意图 — 含 6 模块 + 数值标注 + 配色图例]

3. 两条链路架构

链路 A 有损做法（Week 4 遗留方案）

📷 图片上传↓ 🔍 视觉模型生成文字摘要↓ 📝 摘要："这是一张包含6个模块的架构图..."↓ 🤖 纯文本模型根据摘要回答↓ ❓ 用户得到基于文字转述的答案

链路 B 一步直达（本项目的正确做法）

📷 图片上传↓ 🧠 多模态模型直接看图↓ ⚡ 边看图边推理 + Function Calling↓ ❓ 用户得到基于像素级理解的答案

链路 A 生成的文字摘要

这张图是一个系统架构设计图，包含6个模块：用户端、API网关、消息队列、 微服务集群、数据库集群和监控面板。模块之间通过箭头连接，标注有不同 协议名称。部分模块标有数值。右下角有颜色图例说明。整体结构清晰。

4. 测试问题与结果

问题 1：数数量 （需要精确定位和计数）

问题："图中有几个模块处于红色（故障）状态？"

正确答案：2 个（消息队列和数据库集群右下角数值为红色）

链路回答结果分析
链路 A "根据摘要描述，图中包含6个模块，但摘要未提及任何模块的颜色状态，无法判断。" ✗ 错误 文字摘要丢失了颜色信息 — 这是典型的"只看文字描述"盲区
链路 B "有 2 个模块处于红色故障状态：消息队列和数据库集群。" ✓ 正确 模型直接解析像素颜色，准确定位红色标注的模块

问题 2：读具体数值 （需要精确读取标注文字）

问题："API 网关模块右下角标注的吞吐量是多少？"

正确答案：2.4K req/s

链路回答结果分析
链路 A "摘要仅提到'部分模块标有数值'，未具体说明各模块数值，无法回答。" ✗ 错误 摘要生成时做了模糊化处理，丢失了具体数字
链路 B "API 网关模块右下角标注的吞吐量为 2.4K req/s。" ✓ 正确 多模态模型直接 OCR 读取图片中的数字

问题 3：定位元素 （需要空间推理能力）

问题："监控面板通过什么协议连接微服务集群？"

正确答案：gRPC（监控面板 → 微服务集群的箭头上标注为 gRPC）

链路回答结果分析
链路 A "摘要提到'模块间通过箭头连接，标注有不同协议名称'，但未说明具体哪个模块用哪个协议，无法确定。" ✗ 错误 空间关系（谁连谁）在摘要中完全丢失
链路 B "监控面板通过 gRPC 协议连接微服务集群。" ✓ 正确 模型理解模块空间布局 + 箭头方向 + 连线标注

6. 信息损失分析

信息维度链路 A（有损）链路 B（一步直达）
颜色信息 丢失。摘要不会逐像素描述颜色状态 保留。模型逐像素解析颜色
精确数值 丢失或模糊化（"部分标有数值"） 保留。视觉 OCR 读取具体数字
空间关系 丢失。摘要无法精确描述"谁连谁" 保留。模型理解 2D 布局和连线
构图细节 丢失。摘要天然倾向概括 保留。可回答任意位置的细节
API 调用次数 2 次（Vision → Text） 1 次（Vision 直达）
Token 消耗 图 → 摘要 token + LLM token 仅多模态模型 token

7. 结论

链路 A（有损做法）在 3 个测试问题上准确率为 0%。 根本原因是：图片转文字摘要的过程不可避免地丢失了颜色、精确数值和空间关系等关键视觉信息。 摘要生成器天然会选择"概括"而非"逐像素描述"，导致后续纯文本模型拿到的是一份残缺的"二手资料"。

链路 B（一步直达）准确率 100%，且延迟更低、API 调用更少。 这就是本 Week 5 项目选择 glm-4.6v 作为主推理模型、图片以 image_url 直入 message content 的核心原因。 多模态模型本身就是视觉模型，不应该再绕一道"翻译"。
